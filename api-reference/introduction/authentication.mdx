> How to authenticate with the Bleepay API using API keys.

API keys provide scoped, server-to-server access to your business resources —
vouchers, widgets, accounts, and finance. They are meant for backends and
automation, not end users.

Manage your API keys from the Bleepay app: log in, open your business, and go
to its API keys section to create, rename, revoke, or delete keys.

## Using an API key

Send the key in the `x-api-key` header:

```shell
curl --request GET 'https://payments.bleepay.com/api/v1/vouchers?limit=10' \
  --header 'x-api-key: bs_<your-api-key>'
```

Keys use the format `bs_` followed by 64 hexadecimal characters. The full key
is shown only once when you create it, so store it securely and never expose
it in client-side code, public repositories, or logs.

## HTTP status codes

| Status | Meaning |
| --- | --- |
| `200` | Success |
| `400` | Invalid request (bad parameters, validation failure) |
| `401` | Missing or invalid authentication |
| `403` | Authenticated but not authorized for this resource |
| `404` | Resource not found |
| `429` | Rate limit exceeded |
| `500` | Unexpected server error |

## Rate limits

Each endpoint enforces two independent windows: a per-second limit and a
per-15-minute limit. A request is rejected when either is exceeded.

Most endpoints share a common limit, differentiated by read vs write:

| Operation | Per second | Per 15 minutes |
| --- | --- | --- |
| Read (`GET`) | 20 | 300 |
| Write (`POST`) | 10 | 300 |

A few endpoints differ from the general limits:

| Endpoint | Per second | Per 15 minutes |
| --- | --- | --- |
| Vouchers read | 20 | 600 |
| Code-based entry (`reserve-voucher`, `session-open`, `create-session-voucher`, `create-refund-session-voucher`) | 5 | 300 |
| Voucher negotiate (`negotiate-voucher`) | 1 | 60 |

When a limit is exceeded, the API returns `429 Too Many Requests`.
